# 工作包详解

每个工作包(WP):做什么 → 交什么 → 怎样算完成 → 依赖谁。标「建议」的内容尚未定,以 [open-decisions.md](open-decisions.md) 的结论为准。这一阶段不要求写完整流水线,先把每人的输入、输出、文件格式对齐。

## 全组共用的约定
- 数据字段见 [schema.md](schema.md)。label:1 匹配 / 0 不匹配;neg_type:pos / N1 / N2 / N3。
- 每个模型只交一个分数文件:`pair_id,score`,分数越高越匹配。所有指标由 Aaron 的评估脚本统一计算。
- 阈值只在 val 上选,test 上不调。随机种子要记录。
- 「匹配」的定义(建议):标题里说的每一句图里都不矛盾即算匹配;标题漏说一部分(如黑背白垫的椅子只写「黑色椅子」)不算错。
- 不同人交接的东西都先交「小版本」(一个类别、几千对),跑通了再交全量。

## 依赖顺序
1. Kira WP0 冻结 schema → 其他人都能开始写自己的部分。
2. Kira WP1/WP2 交出小版本 → Jack、Aaron、Jane 用它跑通自己的脚本。
3. 小版本出来之前,大家都有可以独立先做的事(见每人「先做的第一步」)。
4. Sean 的 N3 和 OOD、Aaron 的时间维度数据都复用 Kira 的负例构造思路,所以很早就要在 schema 和分组规则上对齐。

## Kira — 数据底座(WP0–2)
目标:把 ABO 变成大家都能直接用的、干净的「图-文配对表」。

**WP0 冻结 schema(约 2–3 小时)**
- 做什么:把字段写清楚(每列的含义、取值、是否可空),定文件格式(一个 pairs 表 + 一个图片目录)、分数文件格式、split 的名字。
- 交什么:一页 schema 说明贴到组内;组员确认后不再改字段名。

**WP1 ABO 数据底座(1.5–2.5 天)**
- 第一步:下载 listings(abo-listings.tar,约 83MB)和图片元数据;图片先只下小分辨率版,只拉入选商品的图。
- 筛选:只保留有英文(en_US)标题且有主图(main_image_id)的商品。
- 计数:按 product_type 和一级类目路径统计条数,再统计「color/material 的标准化值确实出现在标题里」的条数(决定 Sean 的 N3 能做多少)。这张表贴到组内,类别选择等它。
- 近重复分组:同一商品的不同尺码、颜色版本要归为一组(共享图片 id,或去掉尺码/颜色词后标题相同),给每组一个 group_id。
- 划分:按 group_id 划分 train/val/test(如 80/10/10),同一组绝不跨 split。留出的 OOD 类别不进 train。
- 交什么:items 表(item_id, title, image_path, product_type, node, color, material, group_id, split)+ 类别计数表 + 小版本。
- 完成标准:小版本给出后其他人能读入;检查同一 group_id 没有跨 split。

**WP2 N1/N2 负例(约 1 天)**
- N1(随机负例):每条标题配一张不同 group 的随机图。
- N2(同类难负例):在同 product_type 里选不同 group 且标题最相似的商品的图;相似度用「非 CLIP 的句向量模型」算(建议,待组内确认)。
- 约束:正负 1:1;每条标题各当一次正例、一次负例;负例图与正例图不能是同一组。
- 抽检:每种负例至少人工看 50 对,记下「其实是匹配」的比例。
- 交什么:pairs 表(含 pos / N1 / N2)+ 抽检结论。

**先做的第一步**:起草 schema,并拿 listings 算类别计数表。附读:ABO 论文的字段说明。

## Jack — 模型训练与基线(WP5–6)
目标:把「零样本 CLIP → LoRA 微调 → 全量微调」这条主线跑出来,并交出可以直接对比的分数文件。

**WP5 零样本 CLIP + 全量微调对照**
- 零样本:用 CLIP ViT-B/32,算图和标题向量的余弦相似度作为 score;在 val 上选阈值。
- 全量微调(对照):所有参数都训练,数据和 epoch 与 LoRA 保持一致,用来回答「LoRA 的效果是否接近全量」。
- 交什么:两个分数文件 + 简短说明(用了哪些超参)。

**WP6 LoRA 训练与消融**
- 在 Q/V 投影层加 LoRA(用 peft);训练目标用 InfoNCE + batch 内难负例(建议,待组内确认)。
- 消融:rank = 4/8/16;只微调文本端 / 只微调图像端 / 两边都微调。
- 多种子:每个配置至少 3 个 seed,报告均值和波动。
- 记录:可训练参数量、训练时间。
- 交什么:每个配置一个分数文件 + 一张汇总表(配置、参数量、时间、种子)。

**依赖**:等 Kira 的小版本、Aaron 的评估脚本。

**先做的第一步**:用几十对玩具数据把「读 CLIP → 算相似度 → 加 LoRA → 训几步 → 存分数」这条链跑通。附读:e-CLIP、EI-CLIP 的方法部分。

## Aaron — 评估与时间维度数据(WP4、WP9)
目标:把所有模型的结果用同一把尺子量出来;再补一个不同时间的测试集。

**WP4 评估脚本 + 对照实验**
- 评估脚本:输入 pairs 表 + 分数文件,输出 Accuracy(阈值在 val 上选)、AUC、正例准确率、负例准确率,并按 neg_type / category / year / split 分组汇报;可选算 R@1。输出一张 CSV 和一张 Markdown 表。
- text-only / image-only 对照:用最简单的分类器(如 TF-IDF + 逻辑回归、图像向量 + 逻辑回归)只看标题或只看图来预测 label。如果准确率明显高于 50%,说明数据里有捷径(尤其是 N3,因为标题被改过),要回头修负例构造。
- 交什么:评估脚本 + 一页使用说明 + 两个对照的结果。
- 完成标准:Jack、Jane 的分数文件都能直接丢进去出表。

**WP9 时间维度数据(Amazon Reviews 2023)**
- 先查清楚:商品元数据里有哪些字段、有没有可用的时间信息(我的印象是评论有时间戳、商品本身可能没有上架日期,可能要用最早评论时间代替,需你核实);图片是链接,要估下载量和失效率;确认使用条款。
- 选 1–2 个与 ABO 类别可比的类别,转成和 ABO 一样的 items 表(含 year)。
- 正负例用 Kira 和 Sean 的同一套规则构造,只当测试集,不训练。
- 交什么:时间测试集(同 schema)+ 字段调研结论。
- 时间紧时这一块最先缩:只取一个类别、几千对。

**先做的第一步**:框架和指标列表先写好,用随机分数验证「指标算得对」(随机分数 AUC 应接近 0.5)。

## Jane — GPT-6 Luna 与更多基线(WP7–8)
目标:把老师要求的 Luna 和更多基线都以同样的分数文件格式交出。

**WP7 Luna baseline**
- 先查官方文档:图像输入的调用格式、速率限制、图片怎样计费(我这边没有核实,已确认的只有:支持文本+图像输入、文本输出、有推理强度设置)。
- 设计 prompt:输出 0–100 的匹配概率(阈值 50,算 AUC 也用这个数);两版——P1 直接判断、P2 要求先检查类别/颜色/材质/形状;固定推理强度。prompt 里要写「只有明显矛盾才判不匹配,标题漏说不算」。
- 解析失败的要计数、单独报告,不要默默当作某个值。
- 先小测 20 对,估真实的每次调用费用和耗时再决定跑多少;建议先跑分层抽样的 2k 对。
- 交什么:分数文件(score = 概率/100)+ 费用、解析失败率记录 + 两版 prompt 的对比。

**WP8 更多 baseline**
- 从候选里选 2–3 个(候选:更大的 CLIP、SigLIP、BLIP-2 的图文匹配头等),先确认显卡和显存能不能跑。
- 全部用零样本,分数格式与其他人一致。
- 交什么:每个模型一个分数文件 + 一行说明(版本、参数量)。

**先做的第一步**:核实 Luna 文档里图像输入格式和计费,把结论贴到组内。附读:GPT-6 Luna model card。

## Sean — N3 与 OOD 测试集(WP3、WP10)
目标:造「最容易出问题」的属性替换负例,并把这些负例的质量把关;再造 OOD 测试集。

**WP3 N3 属性替换 + 假负例审查**
- 规则(基于 ABO 字段):把标题里的颜色、材质(可选形状)词换成同一属性词表里的另一个值。
- 只对属性单一、明确的商品替换:color 字段有多个值、或含多色的一律跳过;原来的颜色词必须真的出现在标题里。黑背白垫的椅子就是这样要跳过的类型。
- 避免近义替换:如 Ivory ↔ White、Navy ↔ Blue 属于「换了等于没换」,要用一张「不能互换的近义色」表排除。
- 假负例审查:对 N2 和 N3 各抓 100 对人工看,记录「其实算匹配」的比例;该比例写进论文 limitation。
- 交什么:N3 的 pairs 表(同 schema)+ 规则文档 + 审查结论。

**WP10 OOD 测试集**
- 按 Kira 的分组规则从留出的类别造测试集,复用同一套 N1/N2/N3 规则。
- 建议分两档:近 OOD(相近品类,如家具→家居装饰)和远 OOD(跨度大,如→服饰/鞋靴);这是建议,待组内确认,具体类别等 Kira 的计数表。
- 核查:OOD 类别的 group_id 不能和 train 重叠。
- 交什么:OOD 测试集 + 每档的条数统计。

**先做的第一步**:从 ABO 字段说明里列出可用的属性字段,写出第一版颜色词表。附读:"Turning Adversaries into Allies"、TIGER-FG 里的负例构造部分。
